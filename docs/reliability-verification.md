# Проверка надёжности 0.2.0

Проверка выполнена 12 ноября 2026 года. Изменения сохраняют один оркестратор, декларативные адаптеры и общие инструменты. GUI не добавлен; миграции затрагивают только собственную служебную БД.

## Среда и результат

- .NET 10; PostgreSQL 18 в отдельной тестовой БД, без данных приложения.
- Полный набор: 197 тестов в Windows и 197 в Linux Docker, без ошибок и пропусков. Внешние API Steam/Shikimori не обходились: HTTP-сценарии используют искусственный источник.
- Проверки безопасности инструментов обслуживания: 14 тестов Python stdlib, включая фактические подключения контейнеров, опасные архивы и неподдерживаемые тома.
- JSON Schema Draft2020-12: три схемы, два адаптера, четыре модуля, пример назначения PostgreSQL и пример из руководства прошли проверку.
- Реальный Docker backup/restore сохранил карточку, материалы, SHA-256 изображения и секреты; восстановил очередь/checkpoint; сбросил активные аренды. После пересоздания контейнера worker остались приостановлены. Второе восстановление отказалось перезаписывать существующие тома; исходный тестовый проект не изменился.

## Практические границы

ImageMagick ограничивает свой кэш/потоки; это не предел всего RSS кодеков. Жёсткая общая граница ресурсов задаётся контейнером. Очистка измерена функциональным конкурентным сценарием, а не длительным нагрузочным испытанием большого реального каталога.

Пагинация перечисляет текущие данные и не удерживает снимок между HTTP-запросами. План БД не предсказывает триггеры, генерируемые значения или будущие конкурентные изменения. Прямой экспорт между двумя БД остаётся идемпотентной доставкой, без обещания единой распределённой транзакции.

Инструменты резервного копирования рассчитаны на стандартные именованные тома и одну согласованную установку. Внешняя БД приложения копируется отдельно. Освобождение экспортных резервов опирается на подтверждение владельца назначения. Подготовка release workflow не означает, что версия уже опубликована в GHCR.
