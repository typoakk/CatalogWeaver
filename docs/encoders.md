# Модули перекодирования

Модуль — отдельная папка `encoders/{id}/encoder.json`. Реестр `EncoderRegistry` перечитывает её каждые две секунды. Путь меняется через `Importer:EncodersPath`; в Compose папка подключена как `/app/encoders`. Модули описывают параметры декларативно, как адаптеры источников. Они не являются загружаемыми DLL или скриптами.

Общий драйвер `magick` исполняет инструкции через Magick.NET / ImageMagick. Формат и его параметры находятся в модуле; скачивание, проверки, повторы, хеширование и сохранение находятся в общем конвейере. Для другого алгоритма, которого нет в поставляемой ImageMagick, потребуется добавить драйвер программы. Новый профиль или поддерживаемый runtime формат добавляется одним JSON без пересборки.

Входные изображения сейчас принимаются в JPEG, PNG, WebP, AVIF и GIF. Добавление нового выходного формата не расширяет автоматически набор разрешённых входных форматов.

## Добавление своего профиля

Создайте `encoders/webp-small/encoder.json`:

```json
{
  "configVersion": 1,
  "id": "webp-small",
  "displayName": "WebP для небольших изображений",
  "driver": "magick",
  "format": "WebP",
  "defines": { "webp:method": "6", "webp:alpha-quality": "100" },
  "profiles": [
    { "name": "webp-small70", "quality": 70 },
    { "name": "webp-small-lossless", "quality": 100, "defines": { "webp:lossless": "true" } }
  ]
}
```

После следующего сканирования профили появятся в `GET /api/v1/importer/image-profiles`. Выберите `"imageProfile": "webp-small70"` в `assetPolicies` адаптера. Для немедленного обновления вызовите `POST /api/v1/importer/encoders/reload`. Обычный цикл обновления адаптера может добавить ещё две секунды ожидания.

| Поле | Значение |
| --- | --- |
| `configVersion` | Сейчас `1` |
| `id` | Имя папки: строчные латинские буквы, цифры, дефис; до 24 символов |
| `displayName` | Название модуля для API и будущего GUI |
| `driver` | Сейчас `magick` |
| `format` | Точное имя `MagickFormat`, например `Avif`, `WebP`, `Jpeg`, `Png` |
| `rejectAlpha` | Не пытаться перекодировать источник с альфа-каналом; включено в модуле JPEG |
| `defines` | Общие параметры формата в виде строк `format:option` |
| `profiles` | Именованные профили; имя, необязательное качество 1–100, дополнительные defines |
| `qualityRange` | Необязательное создание диапазона имён по префиксу |

Вместо списка из ста одинаковых профилей можно задать:

```json
"qualityRange": { "prefix": "avif", "minimum": 1, "maximum": 100 }
```

Это создаёт `avif1`–`avif100`. Сам код не разбирает имя `avif80`: связь имени с форматом и качеством задаёт модуль. `qualityRange` можно сочетать с `profiles`, если имена не повторяются. Параметры конкретного профиля переопределяют общие `defines`.

Имена профилей уникальны во всём реестре, начинаются с латинской строчной буквы и содержат до 64 символов: буквы, цифры и дефис. `original` зарезервирован конвейером и работает без модуля. Неизвестный профиль отклоняется при проверке адаптера до скачивания. Формат должен поддерживать чтение и запись изображений в текущем runtime; наличие enum само по себе недостаточно.

## Поставляемые модули

| Модуль | Профили | Настройки |
| --- | --- | --- |
| `avif` | `avif1`–`avif100` | `heic:chroma=444`, `heic:speed=6` |
| `webp` | `webp1`–`webp100`, `webp-lossless` | Метод 4, качество альфа-канала 100 |
| `jpeg` | `jpeg1`–`jpeg100` | Качество из профиля |
| `png` | `png-lossless` | Сжатие PNG уровня 9, без автоматически добавляемых дат |

Число качества — настройка конкретного кодировщика; одинаковые числа разных форматов не означают одинаковый результат. Параметры форматов описаны в [ImageMagick Defines](https://imagemagick.org/script/defines.php) и [WebP Encoding Options](https://imagemagick.org/webp/).

В PNG-модуле `png:exclude-chunk=date,time` исключает автоматически вставляемые даты: иначе один источник, перекодированный в разные секунды, получит разные байты и SHA-256. При создании другого PNG-модуля сохраните этот параметр. Цветовые профили и прочие метаданные этой настройкой не удаляются.

## Проверки и повторы

Для любого профиля действует один порядок:

1. Скачать оригинал один раз и проверить декодирование и ограничения размера.
2. Перекодировать оригинал во временный файл.
3. Проверить фактический формат, декодирование, размеры после ориентации и прозрачность. При неудаче повторно проверить тот же файл.
4. Если обе проверки не прошли, удалить кандидат и перекодировать оригинал ещё раз. Снова выполнить до двух проверок.
5. При исчерпании попыток сохранить проверенный оригинал. При успехе выбрать перекодированный файл, даже если он больше.
6. После фиксации результата удалить временную папку вместе с оригиналом и кандидатами.

При ошибке самого перекодирования проверять отсутствующий файл нечего: конвейер переходит к следующей попытке. Отмена прерывает обработку и не маскируется возвратом оригинала.

Точная сохранность альфа-канала проверяется отдельно от цвета. JPEG не поддерживает его: оригинал сохраняется без удаления прозрачности и без добавления фона. Анимация и исходники глубже 8 бит остаются в оригинале, поскольку текущий runtime использует Magick.NET Q8. Перекодирование не меняет размеры изображения, кроме применения исходной EXIF-ориентации.

`rejectAlpha` объявляется самим модулем. Общая проверка точной прозрачности действует всегда, даже если этот флаг не задан.

## Версии и ошибки модулей

При чтении адаптера сервис разрешает `imageProfile` и добавляет в его каноническую версию `resolvedImageProfile`: формат, качество, defines и хеш. Этот служебный блок появляется в ответе API и снимке очереди; вручную задавать его не нужно. При обычном сохранении он пересчитывается из реестра. При выполнении задания используется зафиксированный блок.

Поэтому изменение или удаление модуля не меняет уже поставленное задание. Следующее чтение адаптера получает новые параметры и другую версию. Старые задания, созданные до добавления модулей, сохраняют исходный хеш JSON и разрешают профиль из установленного реестра; исходный модуль AVIF сохраняет прежние параметры.

Неверная правка сохраняет последнюю рабочую версию модуля, а ошибка видна в `/encoders`. Полное удаление папки убирает профили из нового каталога. Уже действующий адаптер может удержать последнюю рабочую версию и показать ошибку; для нового сохранения отсутствующий профиль выбрать нельзя. Коллизия имён блокирует применение нового набора модулей целиком, сохраняя прежний каталог.

Настройки изображения не содержат путей назначения или секретов. Сохранение по SHA-256, staging, лимит диска и фиксация ссылок остаются ответственностью импортера.

## Выполнение и ограничения

Сервис использует `ProcessImageCodec`: каждая нативная проверка/операция запускает внутренний `--image-worker` в дочернем процессе того же контейнера. Адаптеры используют одинаковый инструмент. Общий семафор `ImageWorkerCount` ограничивает процессы независимо от того, пришла работа из очереди или preview. При отмене/таймауте процесс и его дочерние процессы завершаются до освобождения staging; простого прекращения ожидания нативной функции нет.

`ImageProcessTimeoutSeconds` ограничивает одну операцию; общий бюджет задания/preview ограничивает всю последовательность. Ошибка или таймаут перекодирования продолжает обычную последовательность повторов и fallback. Отмена всей попытки прекращает её. Недекодируемый или зависший при проверке оригинал не публикуется.

`ImageMemoryMiB`, `ImageDiskMiB`, `ImageThreads` задают ограничения ImageMagick. Это ограничения его кэша и потоков, а не жёсткий предел всей памяти кодеков. Общий предел контейнера задаёт Compose. [Справочник настроек](settings.md).
