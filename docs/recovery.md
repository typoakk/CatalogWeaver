# Резервные копии и восстановление

Постоянный том сохраняет данные при перезапуске, но не заменяет резервную копию. Процедура ниже предназначена для стандартного `compose.yaml` с пятью управляемыми именованными томами. Нужны Bash, Python 3, gzip и Docker Compose. Для bind mounts или внешних/общих томов инструменты отказываются от работы: их копируют отдельной согласованной процедурой.

## Создать копию

Из корня проекта с работающим или остановленным развернутым сервисом версии 0.2.0+:

```sh
bash tools/backup.sh /secure-backups/catalogweaver-2026-11-12
```

Папка назначения должна быть новой. Скрипт проверяет раскладку Compose и фактические тома контейнеров, останавливает worker, делает `pg_dump`, архивирует `configuration`, `adapters`, `encoders`, `media`, сохраняет фактический образ контейнера и его ID. Затем создаёт контрольные суммы и маркер `COMPLETE`. Если importer до начала работал, он запускается обратно даже при ошибке создания копии. Частичная папка без `COMPLETE` не считается резервной копией.

Копия содержит пароль БД, API-ключ, необязательную `.env` и другие приватные настройки. Папка создаётся с доступом только владельцу. Храните копию вне Git и отдельно от диска сервиса; при переносе используйте шифрование. Архив файлов допускает только обычные файлы и папки, без символических/жёстких ссылок и специальных объектов.

Копия внешней БД приложения в эту процедуру не входит. Если требуется согласованный откат импортера и приложения, остановите изменения и сохраните внешнюю БД отдельно. Её схемой и восстановлением управляет владелец приложения. Экспортные резервы сохраняются: отсутствие локальной ссылки не доказывает отсутствие внешней.

## Восстановить на чистом окружении

Используйте отдельную папку исходников. Нынешняя `.env` не должна отличаться от копии; лучше начинать без неё. Выберите свободный порт и совершенно новое имя проекта:

```sh
export COMPOSE_PROJECT_NAME=catalogweaver-restored
export IMPORTER_PORT=18770
bash tools/restore.sh /secure-backups/catalogweaver-2026-11-12
```

Восстановление проверяет контрольные суммы и архив, отказывается использовать существующие контейнеры или тома выбранного проекта, загружает сохранённый образ по точному ID, извлекает файлы, восстанавливает PostgreSQL и выполняет миграции этой версии. Аренды импортов/страниц из копии сбрасываются только внутри нового проекта до запуска worker.

API запускается с `IMPORTER_WORKERS_ENABLED=false`, эта настройка и точный локальный тег восстановленного образа записываются в `.env`. `/status` показывает паузу. Проверьте карточки через `/items`, файлы, ключ управления, адаптеры и особенно подключения к внешним назначениям. Для продолжения выставьте `IMPORTER_WORKERS_ENABLED=true` и пересоздайте importer с тем же именем проекта.

Первоначальный проект не удаляется и не перезаписывается. Возвращение к старому проекту требует остановить новую копию перед возобновлением старой, если они пишут в одно внешнее назначение. Не используйте `down --volumes` для обычного отката.

## Что проверять при пробном восстановлении

Сравните количество и содержимое карточек, хеши выбранных изображений, рабочие конфигурации и секреты. Проверьте сброс активной аренды, сохранение cursor и оставшейся части страницы, паузу worker и отсутствие неожиданных записей во внешнюю БД. Выполните ограниченный повтор на тестовом назначении. Только после такого испытания копию следует считать проверенной процедурой восстановления.
