# Запуск через Docker Compose

## Первый запуск

На хосте нужны Git, Docker Engine и плагин Docker Compose. Docker должен запускать Linux-контейнеры; это также поддерживается Docker Desktop в Windows.

```sh
mkdir CatalogWeaver
cd CatalogWeaver
git clone https://github.com/typoakk/CatalogWeaver.git .
docker compose up --build -d
docker compose ps
```

`git clone ... .` помещает исходники в текущую пустую папку, без вложенной второй папки CatalogWeaver. Если репозиторий приватный, Git использует настроенную авторизацию пользователя.

`.env` для первого запуска не нужен. Compose выполняет цепочку:

1. Собрать образ CatalogWeaver.
2. Запустить `bootstrap`: создать постоянный пароль БД и ключ управления, если их ещё нет.
3. Запустить PostgreSQL с созданным паролем и дождаться её готовности.
4. Выполнить `--migrate` для служебной схемы.
5. Запустить API и worker.

`bootstrap` и `migrate` завершаются с кодом 0 после выполнения задачи; это нормальное состояние. Работать постоянно должны `state` и `importer`.

```sh
docker compose exec importer curl -fsS http://127.0.0.1:8080/health/ready
docker compose exec importer cat /data/config/api-key
```

Вторая команда выводит ваш ключ управления. API на хосте: `http://127.0.0.1:8770`, заголовок `Authorization: Bearer <ключ>`. Адаптеры первоначально выключены.

## Откуда берутся зависимости

На хост не устанавливаются .NET, PostgreSQL, ImageMagick или NuGet-пакеты.

- Docker скачивает базовые образы SDK и ASP.NET Core Runtime.
- Стадия сборки выполняет `dotnet restore` и `dotnet publish`, включая Magick.NET и Npgsql.
- Финальный образ содержит ASP.NET Core Runtime, приложение, нативные библиотеки изображений, curl и сертификаты. SDK в финальный образ не переносится.
- PostgreSQL скачивается готовым отдельным образом и работает отдельным сервисом.

При первом построении нужен интернет к используемым реестрам и репозиториям пакетов. Обновление исходников с последующим `docker compose up --build -d` пересобирает изменившиеся слои. Запуск готового локального образа не требует повторной установки пакетов. Обращения к источникам каталога по-прежнему требуют доступа к их API/CDN.

Порядок зависимостей описан в [документации Compose](https://docs.docker.com/compose/how-tos/startup-order/); заполнение пустых томов файлами образа — в [документации Docker volumes](https://docs.docker.com/engine/storage/volumes/).

## Сохранённые данные

| Том Compose | Содержимое | Путь в приложении |
| --- | --- | --- |
| `configuration` | Пароль БД и ключ управления | `/data/config` |
| `state` | Данные служебной PostgreSQL | Отдельный контейнер |
| `adapters` | Рабочие конфигурации источников | `/app/adapters` |
| `encoders` | Рабочие модули перекодирования | `/app/encoders` |
| `media` | Выбранные изображения и staging | `/data/media` |

Docker добавляет к именам томов префикс проекта Compose. Обычный `docker compose down` сохраняет тома. Команда `down --volumes` удаляет также служебную БД, секреты, настройки и изображения; она не подходит для обычного перезапуска или обновления.

Новые тома адаптеров и кодировщиков получают шаблоны из образа. Существующие конфигурации не перезаписываются при обновлении образа. Менять и добавлять адаптеры/модули можно через API; реестры продолжают обнаруживать файлы внутри этих папок автоматически. Папки исходного репозитория в стандартном режиме являются шаблонами, а не работающими томами.

## Необязательная `.env`

```sh
cp .env.example .env
```

| Переменная | Назначение |
| --- | --- |
| `IMPORTER_PORT` | Порт хоста, по умолчанию 8770 |
| `STEAM_API_KEY` | Получение списка ID Steam |
| `CATALOG_DATABASE_CONNECTION` | Существующая БД приложения, имя подключения `Catalog` |
| `IMPORTER_MINIMUM_FREE_BYTES` | Резерв свободного места для изображений, по умолчанию 5 ГиБ |
| `CATALOGWEAVER_IMAGE` | Локальное имя собираемого образа, по умолчанию `catalogweaver:local` |

`IMPORTER_DB_PASSWORD` и `IMPORTER_API_KEY` поддерживаются как необязательные начальные значения для нового тома `configuration`. Утилиты `tools/initialize-local.sh` и `tools/Initialize-Local.ps1` могут создать такую `.env`, но в коротком сценарии не нужны. Это позволяет использовать прежнюю `.env` с существующей служебной БД.

Существующие секреты сохраняются. Если новое начальное значение отличается от уже записанного, bootstrap завершится ошибкой вместо незаметной смены пароля. Ротация пароля БД требует согласованного изменения самой БД и её файла; изменение `.env` не выполняет такую ротацию.

Файлы секретов доступны только владельцу и подключены к приложению для чтения. Они не включаются в образ или Git и не печатаются при автоматическом запуске. Для запуска без Compose можно задать `Importer__ApiKeyFile` и `Importer__DatabasePasswordFile` или обычные переменные подключения/ключа.

## Работа с папками хоста

Если хотите редактировать файлы непосредственно в репозитории и сразу видеть изменения в сервисе:

```sh
docker compose -f compose.yaml -f compose.bind.yaml up --build -d
```

Этот вариант подключает `./adapters` и `./encoders` вместо одноимённых томов. Пользователь приложения в контейнере имеет UID 1654: для изменения конфигураций через API ему нужны права записи в эти каталоги. Права настраиваются под файловую систему хоста. Для чтения и ручного редактирования хостом достаточно обычного доступа к файлам. После выбора варианта используйте те же два `-f` при последующих командах Compose.

Для медиа можно аналогично настроить свой bind mount вместо `media:/data/media`. Путь из адаптера остаётся вложенным относительно `Importer:MediaRoot`. Раздачу файлов выполняет приложение пользователя или файловый сервер, а не управляющий API импортера.

## Обновление

```sh
git pull --ff-only
docker compose build
docker compose stop importer
docker compose run --rm migrate
docker compose up -d --wait
docker compose ps
```

При использовании одной служебной БД прежние worker должны быть остановлены до переключения версии. Стандартный Compose заменяет контейнер импортера, сохраняя данные и секреты в томах. Перед обновлениями, меняющими служебную схему, сохраняйте резервную копию своих данных.

Для паузы фонового импорта задайте `IMPORTER_WORKERS_ENABLED=false` в `.env` и пересоздайте importer. API и preview продолжают работать. Compose ограничивает контейнер по памяти (`IMPORTER_MEMORY_LIMIT`, по умолчанию `1536m`), CPU (`IMPORTER_CPU_LIMIT`, `2.0`) и числу процессов (256). Нативные операции дополнительно ограничены общим количеством дочерних процессов, временем и параметрами кэша ImageMagick. Подробности — [все настройки](settings.md).

[Резервные копии](recovery.md), [поставка и откат](releases.md). Инструменты backup/restore рассчитаны только на стандартные управляемые тома; bind mount вариант требует отдельной процедуры копирования.
