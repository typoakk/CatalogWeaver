# Веб-клиент на ПК и серверный API мониторинга

Мониторинг разделён на два приложения:

- **CatalogWeaver на каждом сервере** считает собственные показатели и хранит свою историю. Dev, Staging и Prod не запрашивают данные друг у друга.
- **CatalogWeaver.MonitorClient на ПК пользователя** получает данные каждого подключённого сервера отдельно и показывает их в браузере. Клиенту не нужны PostgreSQL, импортер или ключ управления сервером.

Все CSS, JavaScript и графики встроены в клиент. Интернет, CDN и облачная авторизация ему не нужны. Для получения новых карточек от внешних источников самому импортеру по-прежнему нужен доступ к этим источникам.

## Запустить клиент

Готовый Windows-клиент автономный, установка .NET не требуется. Запустите `CatalogWeaver.MonitorClient.exe` — он откроет браузер на `http://127.0.0.1:8870/monitor/`. Для сборки из репозитория нужен .NET SDK 10:

```powershell
dotnet publish src/CatalogWeaver.MonitorClient/CatalogWeaver.MonitorClient.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o .local/monitor-client
& ./.local/monitor-client/CatalogWeaver.MonitorClient.exe
```

Форма входа с серверным ключом отсутствует. При первом запуске клиент предлагает добавить сервер. После перезапуска восстанавливает подключения, сохранённые на этом ПК.

Параметры исполняемого файла: `--port 8870`, `--no-browser`, `--Client:DataDirectory PATH`. Клиент слушает только loopback. Его локальный API проверяет Host и специальный заголовок запросов; сторонние веб-страницы не могут изменять подключения через форму или cross-origin fetch.

## Подключить сервер

В «Все окружения → Добавить окружение» укажите:

- название, например Dev;
- способ подключения. Для HTTP(S) укажите корневой адрес API, доступный с ПК. Для SSH укажите хост и порт API на сервере;
- ключ мониторинга именно этого сервера;
- при необходимости описание, цвет, интервал 2–300 секунд, таймаут 1–60 секунд, пороги места и времени без прогресса.

Клиент проверяет подключение и UUID сервера, затем получает список адаптеров автоматически. Переименование, смена адреса и перезапуск сохраняют идентичность. Повторное добавление того же сервера отклоняется. Замена установки по старому адресу на другую с новым UUID требует отдельной записи.

Пустой ключ при редактировании сохраняет прежний. Можно приостановить опрос или удалить подключение; данные исходного сервера сохраняются. Недоступный сервер не задерживает опрос остальных. Последний полученный снимок остаётся видимым с ошибкой связи и временем измерения.

## Где взять ключ

**Ключ мониторинга** разрешает GET собственного API показателей. На сервере его можно получить явной командой:

```sh
docker compose exec importer dotnet CatalogWeaver.dll --monitor-key
```

Вне Compose: `dotnet CatalogWeaver.dll --monitor-key` с обычными настройками этого сервера. Команда намеренно выводит секрет только по явному запросу; не помещайте её вывод в общие журналы. В обычном запуске ключи не печатаются.

По умолчанию постоянный ключ мониторинга криптографически выводится из ключа управления с отдельным назначением. Можно явно задать `Monitoring:ApiKey` (`MONITORING_API_KEY` в Compose), 32–4096 символов без переводов строки. Обновление архитектуры не меняет существующие ключи.

**Ключ управления** остаётся для администрирования импортера через REST API. Он не нужен для открытия локального клиента. Администратор также может получить ключ чтения через авторизованный GET `/api/v1/importer/monitoring-key`; клиент этот маршрут не вызывает.

## Доступ из сети и SSH

В стандартном Compose API доступен на `127.0.0.1:8770` хоста. Если ПК видит API по LAN или через внутренний HTTPS-прокси, выберите **По адресу HTTP(S)**. Для прямого доступа по LAN адрес и порт публикации задаются через `IMPORTER_BIND_IP` и `IMPORTER_PORT`.

Чтобы подключиться к API на loopback сервера:

1. Подготовьте OpenSSH Client на ПК. На Windows клиент мониторинга использует системный `ssh.exe` в `System32\OpenSSH`. На Linux используется `ssh` из `PATH`.
2. Настройте SSH-доступ к хосту и проверьте его в терминале. Ключ хоста должен быть подтверждён, а вход с `ssh -o BatchMode=yes catalogweaver-dev` должен работать без интерактивных запросов. Можно использовать параметры из `~/.ssh/config`, включая `IdentityFile`, агент и `ProxyJump`.
3. В форме окружения выберите **Через SSH**. Введите SSH-псевдоним из конфигурации (например, `catalogweaver-dev`) или `user@host`, порт **HTTP API на SSH-сервере** (обычно `8770`) и ключ мониторинга. SSH-порт при необходимости задаётся в конфигурации OpenSSH.

Опрос открывает SSH-подключение к HTTP API на `127.0.0.1` сервера. После запуска клиента сохранённые окружения опрашиваются автоматически. При обрыве SSH следующий опрос снова подключается к серверу. Для каждого окружения можно задать свой SSH-хост. На ПК доступен только порт веб-интерфейса, по умолчанию `8870`.

Профили со своим внешним SSH-туннелем продолжают работать через **По адресу HTTP(S)**. Чтобы перенести такой профиль в режим **Через SSH**, откройте его настройки, укажите SSH-хост и порт API, а поле ключа оставьте пустым. Сохранение проверит UUID сервера. Лаунчер `tools/Open-Monitor.ps1 -SshHost` доступен для профилей с внешним туннелем.

## Где сохраняются данные

На Windows профили находятся в `%LOCALAPPDATA%/CatalogWeaver/MonitorClient`. Ключи источников защищены ASP.NET Data Protection с Windows DPAPI текущего пользователя и не возвращаются браузеру в списке окружений. PostgreSQL и мастер-ключ импортера для этого не используются. Смена ключа управления одного сервера не шифрует и не удаляет профили остальных; если она изменила его производный ключ чтения, замените ключ только этого подключения.

На Linux для необязательного запуска клиента используются приватный локальный keyring и каталог только для владельца. Копия профилей Windows под другую учётную запись требует повторного ввода ключей.

Сервер хранит UUID, очередь, собственные показатели и историю в своей служебной PostgreSQL. Старая таблица `MonitorEnvironments` от первой реализации при обновлении не удаляется, но сервер больше её не использует и ничего из неё не опрашивает. Новые подключения создаются в клиенте на ПК.

## Показатели

- M1/M5/M15 — успешные карточки в минуту за последние 1/5/15 минут. Первые успешные импорты и обновления считаются отдельно. Неполное окно подписано фактически измеренным временем.
- Успешное завершение фиксируется в одной транзакции с переходом задания importing → completed; потерявшие аренду попытки, ошибки, отмены и частичные результаты не увеличивают счётчик успехов.
- Обзор: очередь, обход, активные этапы, heartbeat, ресурсы, собственная БД и зарегистрированные файлы сервера. ETA ориентировочная при завершённом обходе и накопленной скорости.
- Очередь: фильтр адаптера/состояния, страницы по 100 заданий, результаты, поля, материалы и версия снимка задания.
- HTTP: фактически прочитанные/записанные тела, включая частичные передачи и повторы; категории обхода, метаданных и изображений, ошибки, медиана/p95 и общий лимитер. Пути, query, заголовки и тела не сохраняются.
- Изображения: роли, состояния, запрошенные/фактические профили, объём и проблемы получения. Прежний сохранённый файл не скрывает текущий признак retry.

Серверный снимок обновляется каждые 10 секунд, веб-страница — каждые 5 секунд. История графиков хранится 30 дней с минутным разрешением, выдаётся примерно до 500 реальных точек. HTTP-события хранятся 7 дней; накопительные счётчики не сбрасываются при очистке истории. CPU/память относятся к процессу импортера; дочерние нативные процессы в эти числа не включены.

HTTP-буфер ограничен и пишется идемпотентно примерно каждые 2 секунды. При аварийном завершении возможна потеря ещё не записанного пакета; переполнение отмечается счётчиком. Успешные завершения заданий не зависят от буфера. Исторические значения до включения измерений не выдумываются. Закрытие клиента не прерывает серверные измерения.

## API сервера

Пути ниже требуют `Authorization: Bearer <ключ мониторинга>` и относятся только к данному серверу:

| GET | Содержимое |
| --- | --- |
| /api/v1/monitor/snapshot | Версия формата, UUID, адаптеры, очередь, окна, ресурсы и диагностика |
| /api/v1/monitor/history?hours=1 | История за 1–720 часов |
| /api/v1/monitor/jobs?provider=steam&state=retry&cursor=… | items/nextCursor, до 100 заданий |
| /api/v1/monitor/jobs/{id} | Подробности задания |

На сервере нет общего веб-клиента, cookie-входа или API регистрации других окружений. `/monitor/api/*` существует только в локальном приложении на ПК. Этот процесс отправляет фиксированные GET-запросы в API выбранного источника; перенаправления отключены. Браузер работает с локальным клиентом, CORS на серверах не требуется.
