# Управляющий API

Базовый путь: `/api/v1/importer`. Все маршруты в таблицах требуют `Authorization: Bearer <Importer:ApiKey>`. В Compose ключ создаётся автоматически в томе `configuration`, файл `/data/config/api-key`. Получить его: `docker compose exec importer cat /data/config/api-key`. При запуске из исходников можно задать `Importer__ApiKey` или `Importer__ApiKeyFile`. API предназначен для консольных клиентов и будущего GUI.

`GET /health/live` и `GET /health/ready` находятся вне базового пути и работают без ключа. Стандартный Compose публикует API только на `127.0.0.1:8770` хоста.

## Состояние, источники и модули

| Метод и путь | Назначение / тело |
| --- | --- |
| `GET /status` | Адаптеры, модули, очередь и обход |
| `GET /adapters` | Найденные адаптеры и ошибки |
| `GET /adapters/{provider}` | Канонический JSON адаптера |
| `PUT /adapters/{provider}` | Проверить и сохранить полный JSON |
| `POST /adapters/{provider}/validate` | Проверить полный JSON без сохранения |
| `POST /adapters/reload` | Перечитать адаптеры |
| `POST /adapters/{provider}/enabled` | `{"enabled":true}` или `false` |
| `GET /encoders` | Модули, версии, имена профилей и ошибки |
| `GET /encoders/{id}` | JSON модуля |
| `PUT /encoders/{id}` | Проверить и сохранить полный JSON модуля |
| `POST /encoders/{id}/validate` | Проверить JSON модуля без сохранения |
| `POST /encoders/reload` | Сначала перечитать модули, затем адаптеры |
| `GET /image-profiles` | `original` и разрешённые профили с форматом, качеством, defines и версией |
| `GET /templates/adapters/{id}` | Шаблон адаптера из работающей сборки, версия рабочей конфигурации и отличающиеся пути |
| `GET /templates/encoders/{id}` | Аналогичное сравнение кодировщика без применения изменений |
| `GET /openapi.json` | OpenAPI 3.1, построенный по фактическим маршрутам и типам запросов |
| `GET /schemas/{name}` | `adapter.schema.json`, `encoder.schema.json`, `database.schema.json` |

Проверка возвращает `valid` и `errors`; сохранение неправильной конфигурации возвращает HTTP 400. Временная ошибка ручного редактирования сохраняет предыдущую рабочую версию и появляется в диагностике.

GET конкретной конфигурации возвращает сильный `ETag`. Для PUT существующей конфигурации и POST `enabled` обязателен `If-Match: "<версия>"`: без него HTTP 428, при несовпадении HTTP 412. Изменение проверяется атомарно с записью, включая ручное изменение файла до очередного сканирования. Создание без заголовка допустимо только при отсутствии файла; одновременное второе создание получает 412. `If-Match: *` означает намеренную замену существующего файла независимо от версии; это также позволяет восстановить вручную повреждённый JSON. Для обычного редактирования используйте точный ETag. Переключение enabled выполняет атомарное изменение одного поля.

## Проверки и запуск

| Метод и путь | Назначение / тело |
| --- | --- |
| `POST /adapters/{provider}/preview` | `{"externalId":52991,"processImages":true,"planDatabase":true}` |
| `POST /adapters/{provider}/discovery/preview` | Одна страница ID: `{}` или `{"cursor":"..."}` |
| `POST /adapters/{provider}/jobs` | Выборка: `{"ids":[52991]}`; до 1000 ID |
| `POST /adapters/{provider}/discovery` | Обход: `{"maximumItems":10,"restart":false}` |
| `GET /jobs?provider=steam&limit=30` | Список заданий; также фильтр `state` |
| `GET /jobs/{id}` | Состояние и результат одного задания |
| `POST /jobs/{id}/retry` | Повторить с актуальной версией адаптера |
| `POST /jobs/{id}/cancel` | Отменить задание |
| `POST /jobs/{id}/refresh` | `{"enabled":false}` приостанавливает будущие обновления; `true` возобновляет |
| `GET /discovery` | Позиции обхода и остатки страниц |
| `GET /items?limit=30` | Сохранённые нормализованные карточки |
| `GET /items/{mediaId}` | Карточка и её материалы |

Preview доступен при выключенном адаптере. Без `processImages` локальные материалы остаются запланированными; с ним файлы скачиваются и обрабатываются во временной папке, затем удаляются. Постоянные карточки и файлы не публикуются. Реальные HTTP-запросы всегда расходуют общий лимит источника.

Карточки и discovery разделяют предел `PreviewCount` и бюджет `PreviewTimeoutSeconds`, включая ожидание свободного слота. Истечение бюджета возвращается как `preview_timeout` в общем результате. Нативный дочерний процесс прекращается до удаления staging.

`GET /items` и `GET /jobs` сохраняют массив в теле. При наличии следующей страницы заголовок `X-Next-Cursor` содержит непрозрачный cursor: повторите запрос с `?cursor=...` и теми же фильтрами. Размер страницы 1–100. Карточки упорядочены по `(provider, externalId)`, задания — по `(createdUtc DESC, id DESC)`, поэтому обновление карточки/задания не переносит их между страницами. Это перечисление текущих данных, а не длительный снимок: новые записи могут появляться во время обхода.

Отмена активного задания снимает аренду и запрещает позднюю фиксацию. Отмена `completed` сохраняет успешный результат и ставит `refreshEnabled=false`. Маршрут `refresh` меняет только последующие автоматические обновления; уже начатая попытка может завершиться. Явный повтор ID возобновляет обработку.

В `item.fieldStatus` перечислены настроенные поля со статусами `complete`/`retry`. Успешное пустое значение авторитетно; `retry` и отсутствующее сопоставление сохраняют прежнее поле. Неудачные поля не перезаписывают соответствующие колонки внешней БД или коллекции тегов/жанров. При неполных данных первая вставка, требующая обязательного недоступного поля, назначает повтор.

`planDatabase=true` добавляет план действий по настроенной целевой БД. План строится read-only, без пробных записей, вызова DML-триггеров или расходования последовательностей. Неизвестные значения отмечаются явно. План относится к моменту чтения: при импорте условия проверяются снова.

Для очереди и обхода адаптер должен быть включён. Каждое задание сохраняет версию JSON вместе с разрешёнными инструкциями перекодирования. Обход хранит cursor и остаток страницы в PostgreSQL. Успешно импортированные карточки обновляются по `refreshHours`; завершённый полный обход сам по себе не запускается заново по расписанию.

## Целевая БД

| Метод и путь | Назначение / тело |
| --- | --- |
| `GET /database/{connectionName}/schema` | Прочитать таблицы, колонки, ключи и связи |
| `POST /database/validate` | Проверить тело `destinations.database` по существующей схеме |
| `POST /database/plan` | План для `destination`, `item`, `assets`, необязательных `mediaId` и `adapterVersion` |

Имена подключений выбираются из конфигурации сервиса. API не принимает произвольную строку подключения от клиента и не выполняет пользовательский SQL. Подробности: [сопоставление БД](database-mapping.md), [подключение приложения](service-integration.md).

## Файлы и диагностика

`GET /files/export-reservations?limit=30&cursor=...` возвращает `items` и `nextCursor`; у элемента есть `file`, `revision`, `reservedUtc` и `locallyReferenced`. Для освобождения отправьте в `POST /files/export-reservations/release`:

```json
{"files":[{"file":{"hash":"<SHA-256>","relativePath":"source/<SHA-256>"},"revision":"<UUID из рассмотренного резерва>"}],"confirmation":"external-references-verified-absent"}
```

Подтверждение означает, что вызывающий проверил отсутствие внешних ссылок. Универсальный writer не может автоматически найти все ссылки в произвольном приложении. Изменившаяся ревизия, локальная ссылка или активная публикация сохраняют резерв; ответ содержит `released` и `retained`. Файл непосредственно этим запросом не удаляется. Автоматического срока истечения экспортных резервов нет.

`/status` возвращает `workersEnabled`, очередь, discovery и `loops`: этап, heartbeat, идентификатор попытки, длительность, счётчики и последний безопасный сбой. Ответы об ошибках содержат стабильный код, `retryable`, безопасное объяснение и `traceId`; SQL-значения, ключи и исходные сообщения исключений не публикуются. Ошибки входных значений — 400; постоянный отказ БД/источника — 422; временная недоступность — 503. Источник в preview продолжает использовать общий `ImportResult` с HTTP 200 и статусом внутри результата.
